## Context / Why

This is a bounded checkpoint between M01 (spec 070) and M02, **not** a roadmap packet. The
implementation has moved ahead of how Forge presents itself and of its consumer fixtures:

- the landing page still prints package version `0.4.0` in seven literals and calls the Angular
  story a "future";
- README, `docs/README.md`, `docs/ROADMAP.md` and the `/docs` introduction still describe `0.4.x` as
  current and list query gaps that spec 050 closed;
- `apps/demo-aesthetics` predates specs 047, 050, 052 and 054 in several places. It keeps a bearer
  token in `localStorage`, uses hand-rolled admin content/users pages, and loads whole collections to
  filter in JavaScript. Its `FINDING n` comments describe limits that no longer exist;
- `docs/DEMO-FINDINGS.md`'s "Still open" list names globals and query gaps that shipped;
- tiny-project dogfoods exactly one Strata route.

The goal is to make what Forge already does coherent and demonstrable before M02.

### D. `apps/tiny-project` and Strata

- Published Strata is `@strata-sc/core@0.1.0` / `@strata-sc/analog@0.1.0` (the only versions on npm).
  `@strata-sc/server-components` is not published (npm 404).

## Goal

Current docs, the website and the three consumer apps tell one accurate story about Forge today.
The demo drops every workaround current Forge replaces and keeps only real gaps. tiny-project serves
list **and** single-document reads through Strata with proven H3 parity.

## Non-goals

- M02 (migration runner/ledger) or any other roadmap packet; no spec 072.
- Editing package versions, the pending changeset, PR #54, deploying or publishing.
- Migrating the deployed demo's `site_settings` to a global (needs M02).
- Moving any mutating route (POST/PUT/PATCH/DELETE, auth, uploads) to Strata.
- Consuming `@strata-sc/server-components`, linking Strata source, or making any `packages/*` depend on
  Strata.
- Angular 22 / Analog 2.7 / Vite 8 upgrades.
- A landing redesign, a demo brand redesign, U01–U03 admin certification, new generic components.
- Rewriting historical specs; historical text stays, and statuses are added beside it.
- Replacing `/api/site/*` with browser-side generic CRUD.

## Design

### Release truth

- One statement everywhere current: _npm family `0.7.0` (roadmap 0.6 complete); roadmap 0.7: M01 done
  on `main`, unreleased; M02 next; M03 pending._ No doc says "roadmap 0.7 complete".
- README gets a short "Versions vs roadmap checkpoints" note. The README package table drops the
  per-row `0.4.x` column (the family is fixed; one sentence names the current version).
- The drift-detection docs carry a one-line availability note ("in the release after 0.7.0").

### Website

- `src/app/forge-release.ts`:

  ```ts
  /** The published @forge-cms/* family version (fixed group). Update when a release is published. */
  export const CURRENT_FORGE_VERSION = '0.7.0';
  export const FORGE_PACKAGES = [
    'core',
    'db',
    'auth',
    'storage',
    'api',
    'runtime',
    'cloudflare',
    'angular',
    'admin',
    'testing'
  ] as const;
  ```

  `landing-data.ts`'s `packages` is derived from these (name, purpose, `CURRENT_FORGE_VERSION`).
  Build-time static truth, no npm fetch.

- Positioning: _"Code-first CMS for Angular and Analog, inspired by Payload's architecture: a Local
  API, a reusable Angular admin, Cloudflare D1/R2 first, libSQL for portability."_ Keep the
  experimental/pre-1.0 badge.
- Sections, tightened in place (same components, Volt UI):
  - **hero**: positioning plus the install line;
  - **architecture** → "What works today": the nine differentiators;
  - **Local API**: a two-line snippet inside the architecture section;
  - **packages**: ten cards from one version;
  - **roadmap**: 0.6 complete; 0.7 in progress (M01 done, M02 next, M03 pending); 0.8–0.12 one line
    each.
- New docs page `/docs/schema-upgrades` (group "Client & deploy"). It answers "what happens when I
  change my schema?" from `docs/SCHEMA-UPGRADES.md` without documenting M02. Quickstart, deployment,
  concepts and introduction link to it instead of claiming "no migration step".
- Demo dialog: Escape closes it, and focus goes into the dialog when it opens. Copy updated (test
  count, `/login`).

### Demo

- **Auth:** delete `auth-token.ts`. `provideForgeCms({ baseUrl })` with no `authToken`.
  `login.page.ts` (kept: branded and shows the published demo accounts) calls
  `ForgeAuthSession.login()` and honours a safe `returnUrl` via the exported `safeAdminRedirect` if
  public, otherwise `/admin`. `/admin` children are guarded by `forgeAuthGuard({ signInPath: '/login' })`,
  and users by `roles: ['admin']`.
- **Content admin:** `...forgeAdminContentRoutes()` replaces `collections.page.ts` and
  `collection-detail.page.ts`. `ForgeUsersWorkspaceComponent` replaces `users.page.ts`. Dashboard,
  media, API, settings and analytics stay app-local (app-specific).
- **Typed Local API:** `ForgeCmsRuntime<ServerEnv, DemoCollections>`, where `DemoCollections` is the
  inferred registry type. Mappers take `CollectionDocument<typeof services>` etc. The loose-value
  helpers stay only where values really are loose (populated relations, composite JSON, richtext).
- **`services/[slug].get.ts`:** `runtime.findOne({ where: { slug } })` and
  `find({ collection: 'staff', where: { active: true, specialties: { containsValue: id } } })`.
  The 404 and payload shape are unchanged.
- **Comments:** F10/F14/F15/F8/F12 comments are rewritten or removed. The F4 comment explains the
  deliberate retention.

### Strata

- `src/server/strata/forge-read-context.ts` (app-local, replaces `forge-request.ts`):

  ```ts
  /** READ-ONLY / BODYLESS: never use for a mutating route (no body, no signal, synthetic origin). */
  export function createForgeReadContext(
    request: StrataAnalogRequest,
    params: Record<string, string>
  ): { context: ApiContext<ServerEnv | undefined>; env: ServerEnv | undefined };
  ```

  It throws if `request.method` is not `GET`/`HEAD`, so misuse fails loudly.

- `CollectionsController` gains `@Get('/:collection/:id') read(...)` → `handleRead`. The H3
  `[collection]/[id].get.ts` is deleted, while `.put.ts`/`.delete.ts`/`[collection].post.ts` stay H3.
- Parity: `src/server/strata/read-parity.test.ts` mounts the **former H3 handlers** (defined inside
  the test only) and the **Strata plugin** on two h3 apps (`createApp`/`createRouter`/`toWebHandler`,
  the same h3 1.15 the app runs). Each case fires the identical Web `Request` at both apps and
  compares status, relevant headers and body. No live duplicate route exists.

## Acceptance criteria

1. No current doc or website surface calls `0.4.x` current. Package cards render `0.7.0` from one
   constant.
2. Current docs say: npm `0.7.0` = roadmap 0.6 complete; M01 on `main`, unreleased; M02 next; M03
   pending. None says roadmap 0.7 is complete.
3. `/docs/schema-upgrades` exists, is in the sidebar, and says reviewed migration execution is not
   available yet.
4. The landing states pre-1.0/experimental and does not claim production-ready, Payload parity, SSR,
   S3, automatic migrations or Server Components.
5. `apps/demo-aesthetics` has no `auth-token.ts` and no `localStorage` auth. `/admin` is guarded, and
   after logout `/api/auth/me` from the page is `401` and `/admin` redirects to `/login`.
6. The demo's `services/[slug].get.ts` uses `findOne` and `containsValue`, with a regression test.
7. The demo's runtime is `ForgeCmsRuntime<ServerEnv, …typed registry>`, and the mappers take typed
   documents.
8. `collections.page.ts`, `collection-detail.page.ts` and `users.page.ts` are deleted in favour of
   package routes/components.
9. `site_settings` stays a collection. README and DEMO-FINDINGS explain why (persistent D1, M02).
10. DEMO-FINDINGS distinguishes the original finding, package fix, demo status and remaining limit.
    "Still open" lists only real gaps.
11. tiny-project serves `GET /api/v1/:collection` and `GET /api/v1/:collection/:id` through Strata.
    Parity tests prove identical status/headers/body with the former H3 handlers. All mutations stay
    H3.
12. No `packages/*/package.json` gains a Strata dependency, and no `@strata-sc/*` code appears in
    tiny-project's browser build.
13. No package version, Angular, Analog or Vite version changes.
14. All gates in the Test plan pass, or each non-passing one is reported with its reason.

- demo:
  - cookie session and guard, `auth-token.ts` deleted, plus a one-off cleanup of the old stored

  - package content/users routes;

  - `findOne` + `containsValue`;
  - comments;
  - README and DEMO-FINDINGS;
- tiny-project: Strata `read` route, `createForgeReadContext`, parity and registration tests, README;
- the Forge ↔ Strata note and the future Server Component slice in ARCHITECTURE.md.

**Found and fixed beyond the plan:**

- `@forge-cms/admin` (patch, `.changeset/admin-list-populates-relations.md`):
  - the workspace list now requests `depth: 1` (relation and upload cells were ids);
  - wide lists and the users table scroll in place (the rows' `sr-only` labels escaped the page);
  - the sidebar and theme toggles and boolean switches have accessible names.
- Demo:
  - `str()` on SQL `Date` reads blanked production dates, now `isoDate()` (**new finding 24**, the
    package side deferred to 0.8 C02 because it changes public types and adapter output);
  - specialist photos never rendered (no `depth`);
  - the browser cached `/api/site/*` for 60 s (now `max-age=0`, `s-maxage` kept);
  - `withAuthFields(defineCollection(…))` inline widened the registry's slugs;
  - e2e specs get their own throttle bucket (`e2e/visitor.ts`), because a full local run tripped the
    demo's 12 writes/minute guard.

**Divergences from Design** (no behaviour impact):

- `FORGE_PACKAGES` is `{ name, purpose }[]`;
- `createForgeReadContext` returns an `ApiContext` (with `env`);
- the service-detail queries live in `server/api/service-detail.ts` (testable without h3);
- related services are `limit: 3` with `id: { ne }`, and staff are sorted by `order`;
- the login `returnUrl` check is inline, because `safeAdminRedirect` is not a public export.

**Recorded, not changed:**

- Release number: the pending M01 changeset is `minor`, so PR #54 would publish `0.8.0`. The
  maintainer chooses `0.7.1` (edit it to `patch`) or `0.8.0`.
- The `vX.Y.Z` GitHub tags point one merge later than the published source.
- Both deployed apps return 500 on every API route and have no Pages secrets; set `AUTH_SECRET`, then
  run `planSchema()` on both D1 databases.
- The pre-existing `<button volt-button>` in the admin layout (the mobile nav and sidebar toggles) is
  unstyled on Volt 1.0.x, which has only the element selector. They are named now but still render as
  plain buttons.
- There is no docs-nav unit test for the new page; the E2E covers it.
