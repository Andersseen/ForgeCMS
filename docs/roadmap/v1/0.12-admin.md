# 0.12 — Reliable existing editorial workflows

Status: proposed. Outcome: an external consumer's editor completes existing content/users workflows
without host-specific business glue. Entry: 0.11 and stabilized SDK/server behavior. Finding: F17.
Owner: admin implementer; QA owns rendered interaction and browser evidence.
Read: admin workspace/editor/form/field/confirm/auth/users components, query/error helpers, route
factories, existing www and tiny-project consumers; spec 056 to avoid duplicating completed polish.

## U01 — Reliable content state and failure recovery

- **Depends on:** C01–C03, S03. **Scope:** existing admin components/helpers and tests; SDK only for
  a proven generic defect handled separately. No new component catalogue.
- **Deliver:** observable loading/empty/error/saving states; prevent duplicate submits; keep entered
  data after validation/server failure; define unsaved-change navigation and cancelled-delete behavior.
  Preserve query state across list/editor transitions and ignore stale responses.
- **Acceptance:** failed save leaves form data available and displays server field errors; cancel
  leaves data unchanged; success updates the intended list/page only; query/filter/sort/page refresh
  is predictable. A demoted/session-expired user cannot complete a protected operation, and the UI
  reacts to the real server error. No silent lost input on routine recoverable failure.
- **Tests:** rendered component interactions plus tiny-project CRUD/publish/validation/browser cases.
  Pure helpers get unit tests; no assertions of private methods as the acceptance criterion.
- **Handoff:** workflow state contract and focused regressions for U02/U03.

## U02 — Keyboard, focus and existing field interactions

- **Depends on:** U01. **Scope:** existing admin templates/styles/controls, using established UI
  primitives. No design-system replacement, new richtext editor or arbitrary custom-widget API.
- **Deliver:** label/error association, keyboard operation, modal focus containment/return, visible
  focus, responsive layouts and safe existing relation/media/locale controls. Audit existing 056
  semantics first. Preserve error text meaningful to a consumer, not implementation diagnostics.
- **Acceptance:** keyboard-only user can sign in, create/edit/publish/delete with confirm, choose a
  relation, correct invalid input and sign out. Dialog focus returns to trigger; errors are discoverable;
  mobile viewport does not hide the primary action. Unsupported field combinations show the agreed
  explicit behavior instead of accepting data the runtime cannot honor.
- **Tests:** component keyboard/focus tests, automated accessibility checks for relevant pages and a
  recorded keyboard browser journey. Automated tools complement interaction review, not replace it.
- **Handoff:** supported field/editor matrix and remaining non-blocking UX issues with owner.

## U03 — Certify admin reuse and freeze 1.0 surface

- **Depends on:** U01–U02 and all preceding server/client packets. **Scope:** tiny-project/demo
  integration, route/configuration guide, public contract inventory; targeted bugs get separate PRs.
- **Deliver:** install/mount admin under a consumer-selected path, with configured API/auth endpoints,
  roles and navigation using public helpers. Exercise content and users without copied orchestration.
- **Acceptance:** first admin → sign in → create relation/draft → publish → public read → edit →
  delete → logout works; viewer/editor/admin boundaries remain enforced by the server. Users CRUD,
  last-admin handling and invalidated session UX follow H02/H03. Custom mount and refresh work.
- **Tests:** tiny-project and existing www/demo suites, packed production consumer and API negative
  requests even when forbidden controls are hidden. No consumer imports private source.
- **Handoff:** signed final 1.0 export/route/configuration inventory, peer matrix and migration notes.
  Freeze actual signatures/defaults now; 0.13 contains certification and fixes, not feature work.

## Exit / exclusions

No blocking existing user journey, inaccessible primary action or required app-side workaround for
generic CRUD/auth remains. Current UI is certified; no need for a new dashboard, media-library
product, saved filters, bulk actions, visual preview/history, custom-component API or email UI.
