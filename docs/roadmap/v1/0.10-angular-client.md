# 0.10 — A reusable Angular client contract

Status: proposed. Outcome: a consumer can call the whole supported API from its own mount point with
honest types and structured errors. Entry: server contract/data minors complete. Findings: F13, F16.
Owner: Angular implementer; architect owns transport type/error design.
Read: angular service/types/query/resources/auth-session, runtime typed API/errors/handlers,
admin consumers and packed release verifier.

## C01 — Configurable transport and consistent errors

- **Depends on:** B02, H03–H04, 0.9. **Scope:** Angular config/service/session, tests and narrow admin
  call-site adaptations if needed. No server-side access redesign.
- **Deliver:** explicit content and auth base configuration, consistent URL/identifier encoding,
  credentials policy and injectable transport boundary usable by S01. Preserve existing defaults.
  Normalize failures while retaining HTTP status, server code/message/details and distinguish
  unauthenticated from network/server failure. Define cancellation and unexpected-response behavior.
- **Acceptance:** content plus login/me/users/logout work beneath a custom path; same-origin default
  still works. A 409 retains constraint details; 400 retains field errors; 403 is not reinterpreted as
  login expiry; `/me` outage is not silently treated as signed out. Tokens are not forwarded to an
  arbitrary caller-controlled origin. No automatic retry of non-idempotent writes.
- **Tests:** service/session/query unit tests and real HTTP fixture with custom mount. Test malformed
  JSON/network failure, encoded IDs, 401 notification and failed logout state. No global fetch mock
  alone as integration evidence.
- **Handoff:** approved configuration/error contract and migration note for consumers.

## C02 — Honest schema-to-wire types

- **Depends on:** C01 and A/D supported matrices. **Scope:** angular types and type-only shared core
  exports if approved, type fixtures and docs. No runtime schema/hook objects in client bundles.
- **Deliver:** a typed collection registry path that does not require a codegen tool, plus an explicit
  untyped escape hatch. Distinguish create/update data from read projections and populated/localized
  results. Account for hidden fields and nullable/omitted targets; do not claim all schema fields are
  always present in an authorized response.
- **Acceptance:** invalid slug, field or payload fails a consumer compile test; valid CRUD and draft
  workflow compiles without broad casts. Population at depth 1 has the actual return shape and
  inaccessible fields are not falsely guaranteed. Private hooks/auth config never enter browser JS.
  Keep public generics compatible or document intentional pre-1.0 migration.
- **Tests:** positive and `@ts-expect-error` cases checked by tsc, actual HTTP response fixtures and
  packed-consumer build. Compile-only tests do not prove response projection; retain A03 regressions.
- **Handoff:** final SDK typing model consumed by SSR/admin and the public guide.

## C03 — Resource reliability and peer compatibility

- **Depends on:** C01–C02. **Scope:** existing Angular resources/session, package peer metadata,
  consumer build tests. No new resource abstraction or Signals API replacement.
- **Deliver:** stale-request/cancellation behavior, loading/error/reset contract and credential-change
  behavior. Choose supported Angular/Analog/Vite/TypeScript peers from strict actual installs; resolve
  current development-versus-peer pins without speculative widening.
- **Acceptance:** slow old query cannot replace newer results; failed save cannot be reported as
  success; credential switch does not reuse the previous user's data. Supported minimum and selected
  latest versions within declared ranges install without unmet-peer exceptions and build/link in
  production. Existing API-key/browser auth flows remain compatible.
- **Tests:** deterministic delayed-response resource tests, mounted-consumer journey, strict packed
  installation/build matrix. Add only enough versions to justify the advertised support policy.
- **Handoff:** compatibility matrix and stable request boundary for S01.

## Exit / exclusions

The SDK no longer assumes `/api/auth` regardless of configuration, loses important error metadata,
or overstates inferred data. Full client and consumer gates pass. SSR is deliberately next minor;
exclude HTTP client rewrite, codegen CLI, new Angular package and new UI components.
