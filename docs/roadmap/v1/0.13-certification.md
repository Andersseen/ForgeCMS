# 0.13 — External-consumer certification

Status: proposed. Outcome: a fixed candidate proves the complete product promise outside workspace
shortcuts. Entry: all prior exit gates and U03 surface freeze. Owners: integration/QA and release.
Read: release verifier, CI, support/coverage matrices, upgrade fixtures and all unresolved findings.

## R01 — Packed production consumers and durable profiles

- **Depends on:** U03, M03, S03. **Scope:** verifier/fixtures/CI and docs. Generic discovered defects
  get narrow regression PRs; do not hide fixes inside the fixture.
- **Deliver:** clean temporary consumers install only packed candidate packages, with no workspace
  aliases, undeclared peer help or deep imports. Build server and Angular/admin production output.
  Include portable libSQL content and Cloudflare D1/R2 content/files profiles.
- **Acceptance:** basic TypeScript server consumer can use core/runtime without importing Angular;
  Angular/Analog consumer builds and runs through public exports and linker. Critical browser journey
  runs on each durable profile, persists across process restart, and exercises upload only on R2.
  All retained subpath exports resolve. Strict peer installs pass advertised compatibility fixtures.
- **Tests:** packed imports/types, production server HTML/hydration, login/CRUD/publish/reload/logout,
  R2 upload/read/delete, M03 upgrade path. Do not run the entire browser matrix against every backend.
- **Handoff:** artifact hashes, candidate commit, support-matrix results and reproducible commands.

## R02 — Close measurable reliability gaps

- **Depends on:** R01 and B04. **Scope:** tests/performance fixtures, coverage and release reports;
  code fixes only for measured regressions and in separate PRs. No speculative optimization sprint.
- **Deliver:** meet QUALITY coverage floors, close all critical uncovered behaviors and report
  flakiness. Use a fixed realistic fixture for query/count/population/upload/list rendering; record
  DB calls, latency distribution, memory/bundle size, runtime and dataset.
- **Acceptance:** three consecutive isolated critical-journey runs with no unexplained flakiness.
  Establish measured budgets before accepting performance work; common reads are bounded, malformed
  deep queries cannot cause unbounded work, no accidental N+1 regression. Investigate failure branches
  instead of increasing timeouts or hiding assertions. No secret/internal error leakage in logs.
- **Tests:** complete unit/type/contract/real backend/HTTP/browser/upgrade suite and agreed fixed-load
  cases. Use deterministic faults for outages and interrupted mutations. No dependency on live traffic.
- **Handoff:** coverage artifacts, performance baselines, all known issues classified and owned.

## R03 — Rehearse deployment and recovery

- **Depends on:** R01–R02, M03. **Scope:** runbooks and authorized isolated staging. This roadmap
  authorizes no external deployment; prepare a concrete candidate and plan before requesting any
  final authorization not already provided by the implementation session.
- **Deliver:** staging manifest identifying expected D1/R2/auth bindings, secret injection, startup
  migration, health diagnostics, persistence verification and recovery steps. Portable profile has
  equivalent documented persistence and backup validation.
- **Acceptance:** deployed runtime uses intended durable adapters and cannot silently fall back to
  InMemory when a required production binding is missing. Login/cookie/CSRF/content/file flows work
  over the actual served origin; data persists across deployment/restart. Restore a backup into an
  isolated target and verify auth/content/files, never overwrite production for a test.
- **Evidence:** exact commit, environment/profile, logs with secrets redacted, command outcomes,
  actual recovery limits. Local workerd evidence is recorded separately from remote evidence.
- **Handoff:** deploy/recovery runbook and profile certification. Without credentials/authorization,
  keep remote gate pending; do not claim production certification from local tests alone.

## R04 — Consumer documentation and release dossier

- **Depends on:** R01–R03. **Scope:** consumer docs, package metadata/readmes, changelog, support
  policy and release dossier. No new APIs.
- **Deliver:** one short server-only start, one Angular/Analog start, auth/setup guide, access defaults,
  full API/options reference, supported field/profile matrix, error troubleshooting, upload limitation,
  upgrade/backup guide, security reporting and compatibility/deprecation policy.
- **Acceptance:** a reviewer follows the guides from an empty directory without repository-private
  files or undocumented workarounds. Every advertised feature/version has a passing matrix row.
  Migration from retained 0.x APIs is explicit. No stale “not published” or unsupported production
  claim remains in current entry documents. Historical specs remain clearly historical.
- **Handoff:** candidate dossier containing commits/artifact hashes, all checks, coverage, peers,
  consumers, upgrade/deployment results, issues and named release owner.

## Exit / exclusions

No critical/high authorization, credential or integrity finding; no missing required profile gate.
Lower-severity accepted issues have user effect, workaround, owner and follow-up. No features during
certification. A required API break reopens the earlier design/migration and dependent certification.
