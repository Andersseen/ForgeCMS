# 0.10 — Portable storage and deployment profiles

Status: **complete** (P01 spec 082, P02 spec 083, P03 spec 084 — 2026-10-08). Owner: storage/integration implementer with
adapter-contract review. Finding F15. Follow [EXECUTION.md](EXECUTION.md).

## Goal

Both official profiles persist complete small-project content, including files: Cloudflare D1/R2
and portable libSQL/S3 on a tested standard runtime. Cloudflare remains the preferred profile.

## Why now

Spec 055 proved portable users/auth/content/relations/drafts. Durable files are the major remaining
portability hole and belong before 1.0. One S3-compatible adapter closes it without a provider zoo.

## Existing foundation

At `28ff76c`, storage exports only InMemory; the durable implementation is R2 in cloudflare (P01 has since added `@forge-cms/s3`).
StorageAdapter already defines `init`, `put`, `get`, `delete`, `list` and `getPublicUrl`, with shared
contracts and runtime upload/cleanup tests. _(Historical, at spec time:)_ no S3 adapter was implemented. Recheck at implementation
time; if one has since landed, certify/integrate it instead of recreating it.

## Scope

P01–P03: one basic S3-compatible adapter (target `@forge-cms/s3`, or repository-appropriate placement),
contract/lifecycle parity and complete deployment/backup guides. Read storage/R2 implementations,
testing contracts, runtime files/handlers and D01/D04/M03 outcomes. Verify SDK/provider details from
primary documentation at implementation time.

## Non-goals

No direct/presigned uploads, image transforms, CDN system, provider-specific adapter families,
new databases, storage marketplace or universal portability claim. Public URLs do not grant access
to protected media: preserve the runtime file-access contract and document bucket/public URL policy.

## Implementation packets

### P01 — Basic S3-compatible StorageAdapter — complete (spec 082, 2026-10-07)

> Delivered as `@forge-cms/s3` (AWS SDK v3, exact pin) and verified against a real **Garage** `v2.4.1` container
> (`pnpm test:s3`, CI-gated); MinIO was dropped because community binaries/images are no longer published. AWS S3,
> Backblaze B2 and Wasabi are documented configurations, not certified.

- **Depends on:** B02 storage contract and D01/D04 lifecycle semantics. **Scope:** one adapter,
  package/export configuration, matching contract tests and configuration docs.
- **Deliver:** standard endpoint, region, bucket, credentials, addressing-style and public-base-URL
  configuration as supported by the selected implementation. Target AWS S3, MinIO (replaced by Garage in spec 082), Backblaze B2 S3,
  Wasabi and compatible services through configuration, not separate integrations. Choose exact
  options, runtime/SDK dependency and package/fixed-family placement in the approved spec.
- **Acceptance:** put/get/delete/list/public URL match StorageAdapter, including bytes, content type,
  metadata, missing objects, key encoding and list pagination behind the existing contract. Secrets
  stay server-side and absent from logs/bundles. Unsupported provider behavior is explicit; examples
  do not imply every named provider has been tested.
- **Tests:** `runStorageAdapterContractTests` from `@forge-cms/testing/contracts`, focused error and
  metadata cases, plus integration against a real isolated S3-compatible service (e.g. MinIO — Garage in spec 082).
- **Handoff:** adapter/configuration contract, tested runtime/provider versions, documented limits,
  changeset and packed entry-point verification. Preserve existing storage APIs.

### P02 — Portable upload lifecycle and access — complete (spec 083, 2026-10-08)

> Certified on on-disk libSQL + `@forge-cms/s3` + the same Garage `v2.4.1` container (one `pnpm test:s3` run, three
> stages): `apps/tiny-project/src/tests/portable-storage.integration.test.ts` (18 cases) and a two-process packed
> consumer (`scripts/verify-portable-storage-consumer.mjs`). No generic runtime defect was found; R2 tests unchanged.

- **Depends on:** P01, A04, D04. **Scope:** runtime integration/fixtures and focused generic fixes
  with regression evidence; no alternate host-only upload pipeline.
- **Deliver:** libSQL/S3 upload → metadata persist → authorized read/public URL where allowed →
  restart/reload → delete, using existing runtime handlers. Reuse the R2 failure/access scenarios.
- **Acceptance:** files survive restart; validation/size/type and denied reads agree with R2's
  supported behavior. DB failure after object creation and object-delete failure follow the D01
  cleanup/recovery contract. Missing objects and dependency outages are distinguishable as specified.
  Do not claim a cross-database/object-store transaction.
- **Tests:** real libSQL + isolated S3 integration, deterministic fault injection, retained R2 tests
  and a minimal packed-consumer file journey. No need to run all browser tests for every provider.
- **Handoff:** complete storage/profile matrix and migration/recovery implications for P03.

### P03 — Complete deployment and recovery guides — complete (spec 084, 2026-10-08)

> Two durable profiles, production-built from packed public packages: **Cloudflare** (Pages under local workerd +
> local D1 + local R2) and **portable Node** (`node-server` + on-disk libSQL + `@forge-cms/s3` against Garage
> `v2.4.1`). Each walks bootstrap → SSR → hydration → multipart upload → `handleFile` → restart → delete; production
> refuses to start without a complete profile (a `tiny-project` policy, not a runtime concept). M03 backup/restore
> now has a real libSQL + S3 lane (`pnpm test:s3 recovery`, isolated empty target bucket) next to the unchanged
> D1/R2 lane. No `packages/*` change. Runbook: `docs/BACKUP-RESTORE.md`; guides: `/docs/deployment`.

- **Depends on:** P02, M03, C03, S03. **Scope:** consumer/profile fixtures, guides and targeted
  integration fixes. Reuse tiny-project or a minimal companion consumer; no showcase redesign.
- **Deliver:** Cloudflare D1/R2/Workers-or-Pages and portable libSQL/S3/standard-runtime paths from
  clean install through setup, auth/admin, typed public SSR, uploads, deployment and upgrade.
  Extend M03 backup/restore to S3 objects and DB references. Record endpoint/credential injection,
  public/private serving, persistence and recovery limits; production cannot silently use InMemory.
- **Acceptance:** both profiles restore usable content/users/files into isolated targets and retain
  identity/reference integrity. Consumer setup uses public packages without private Forge glue.
  Advertised runtime/provider support matches evidence; named configurable providers are not a
  mandatory certification matrix for every release.
- **Tests:** packed consumer build, minimal durable-file/browser journey per profile, upgrade/restore
  fixtures and production SSR smoke. Record local service evidence separately from remote staging.
- **Handoff:** profile guides and reproducible evidence for U03/R01/R03. Remote deployment follows
  the implementation session's authorization; this planning document does not deploy anything.

## Dependencies

Storage work needs B02, A04 and D01/D04, not completion of unrelated UI work. The 0.10 release adds
M03 upgrades and C03/S03 consumption to the complete profile journey. It follows 0.9 in the product
sequence; its adapter implementation can start earlier once actual contracts are stable.

## Acceptance criteria

One S3-compatible adapter and R2 satisfy the basic durable storage contract. libSQL/S3 is a credible,
documented small-project profile with files, auth, typed Angular/SSR and recovery. Cloudflare-first
does not mean Cloudflare-only; no claim of running everywhere is made.

## Required tests

Shared storage contracts, real S3-compatible and libSQL integration, retained D1/R2 evidence,
access/failure tests, packed consumers and isolated backup/restore. Exact commands: `pnpm test:s3` (stages adapter, lifecycle, consumer, recovery, profiles), `pnpm test:upgrade`, `pnpm release:ssr`. Apply [QUALITY.md](QUALITY.md) and common gates.

## Release gate

**Met (2026-10-08):** P01–P03 pass with profile docs and test evidence. Both durable file paths are required for 1.0.
Do not defer the portable-storage gap to final certification or expand it into advanced media.
