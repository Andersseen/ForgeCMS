# 0.5 — Contract and access foundation

Status: proposed; not implementation authorization. Packet IDs are stable planning references,
not spec numbers, releases or mandatory PR boundaries. Follow [EXECUTION.md](EXECUTION.md).

## Goal

We know what Forge promises, release evidence is required, and every existing content path obeys the same core authorization model.

## Why now

Small-project usability already exists. Close alternate-path access gaps immediately and establish a useful contract baseline before building the Angular/Analog differentiator.

## Existing foundation

Specs 019–055 provide Local API, typed schemas, hooks, access, auth, content lifecycle and external-consumer verification. Spec 056 is complete; its redirects, dialog semantics and UI/docs polish are the baseline, not future work.

## Scope

B01–B04: inventory, current-state reconciliation, CI and coverage baseline. A01–A04: versions, preview, population, globals and remaining access paths. Owners: runtime, QA/infrastructure and documentation; architecture review for policy. Findings F01–F06, F11, F15–F16. Read package exports, CI/verifier, runtime operations/access/field-access/populate/versions/globals/handlers and tests.

## Non-goals

No new fields, auth providers, admin redesign or adapter implementation. This milestone inventories the S3 gap; 0.10 closes it. Do not remove shipped APIs without a specific maintainer decision and migration.

## Dependencies

Verified 0.4.x/spec 056 baseline. B02 defines contracts for A01–A04; B03/B04 establish evidence alongside the access work. Confirmed exposures receive immediate current-line patches without waiting for baseline paperwork.

## Implementation packets

### B01 — Reconcile implementation documentation

- **Depends on:** baseline only. **Scope:** CLAUDE, STATE, ARCHITECTURE, CONVENTIONS, docs index;
  historical specs remain historical. Production code is excluded.
- **Deliver:** concise current package/status tables, current request pipeline, open-debt register
  with evidence and links to this roadmap. Move historical narrative out of the current snapshot
  where needed; mark superseded claims instead of silently erasing decisions.
- **Acceptance:** no current claim that globals/versions/admin do not exist; E2E/backend commands
  match package scripts; Local access defaults and nested error details match source. Every open
  finding has an ID, evidence, owner and target packet.
- **Check:** documentation link/format checks and a reviewer comparing each edited contract to source.
  No new tests for prose. **Handoff:** a source inventory B02 can trust.

### B02 — Inventory and classify the public API

- **Depends on:** B01. **Scope:** documentation and public-surface inspection of all ten packages,
  including `@forge-cms/testing/contracts` and `@forge-cms/admin/vite`.
- **Deliver:** export/route/configuration inventory with columns for symbol, owning package,
  behavior/default, supported profiles, stability decision, tests and migration obligation.
  Include exported adapter implementations/helpers, error classes, hooks, admin selectors/inputs,
  not only headline runtime methods. Decide status of existing globals/version/preview combinations.
- **Preserve:** lists `{ data, meta }`, items `{ data }`, canonical errors
  `{ error: { code, message, details? } }`, empty `204`; record auth-specific responses separately.
  Record actual metadata fields, `/api/v1` vs `/api/auth`, query defaults/limits, partial `PUT`,
  null/omitted/date/localized/populated wire values and Local `overrideAccess: true` default.
- **Acceptance:** every export/route has a row; every planned incompatibility has a dedicated packet
  and migration note. No implementation removal just because something is absent from the MVP table.
- **Handoff:** architecture-approved contract inventory. Signature changes need individual specs;
  this packet does not change the API or introduce OpenAPI generation infrastructure.

### B03 — Make existing evidence release-required

- **Depends on:** B01; B02 defines support profiles. **Scope:** `.github/workflows/ci.yml`, existing
  package/root scripts only if necessary, test artifact settings. No product logic.
- **Deliver:** explicit libSQL and tiny-project browser jobs; demo journey gate on affected changes
  and release; aggregate required status; publish dependencies that wait for all applicable gates.
  Preserve existing Cloudflare, www, packed-install and changeset checks. Account for fresh-clone
  build order; parallel jobs need their own build/artifact prerequisites.
- **Acceptance:** a package change cannot publish after a failed/missing backend or consumer gate;
  logs identify each suite; release candidate always runs the full matrix. A docs-only PR cannot
  accidentally trigger publishing. Validate workflow conditions without performing a publish.
- **Tests:** run available commands listed in QUALITY; inspect job dependency/skip logic. Split
  workflow wiring and any necessary script work into child PRs if their combined scope grows.
- **Handoff:** CI job names and evidence locations for every later packet.

### B04 — Establish coverage and contract-diff baselines

- **Depends on:** B02, B03. **Scope:** Vitest configuration/scripts, test-only infrastructure,
  public API baseline artifacts. Any coverage dependency requires a stated reason.
- **Deliver:** all-source package coverage, non-regression ratchet, target gaps assigned to packets,
  and a reproducible public-declaration/HTTP contract diff check. Prefer a small existing-tool
  solution; do not create a general SDK/codegen platform.
- **Acceptance:** an unimported production module lowers coverage; a removed export or changed
  fixture contract is visible; reports distinguish UI templates and pure types. Every retained
  contract has linked test coverage or an explicit gap packet. No arbitrary exclusions to pass.
- **Tests:** demonstrate the guards detect a temporary missing export/untested branch in an isolated
  check, restore the fixture, then pass the real baseline. Do not commit deliberate failures.
- **Handoff:** measured starting coverage, accepted target policy, public surface baseline.

### A01 — Authorize history reads and restore

- **Depends on:** B02. **Scope:** runtime versions and shared operation policy, history handlers,
  relevant tests; core only if an approved type change is necessary. No history UI.
- **Deliver:** list/get version reads verify the owning document's current read policy and project
  readable fields; restore checks update/field-write policy and follows current validation/hook
  behavior. Define behavior for deleted owner, disabled versions, old schema and inaccessible owner.
- **Acceptance:** an unauthorized caller cannot enumerate/read private snapshots or restore one;
  an authenticated caller denied by a row rule is still denied. Hidden snapshot fields do not leak.
  A forbidden/invalid restore leaves document and history unchanged. Trusted Local override remains
  explicitly available; HTTP cannot set it. Authorized restore creates the intended history once.
- **Tests:** extend versions unit/integration tests, handler tests and real-backend access cases.
  D03 owns atomic history writes; this packet must not claim atomicity it has not implemented.
- **Handoff:** permission/restore pipeline contract for D03; changeset and any migrated semantics.

### A02 — Make preview obey caller policy

- **Depends on:** A01's shared-policy decision. **Scope:** runtime preview method/types, preview
  handler and tests. No preview tokens, live iframe or visual editor.
- **Deliver:** separate existing-document and new-document preview policy. Existing preview must
  check relevant read/edit permissions; new preview checks create/field-write rules. The spec fixes
  exact denial semantics before coding. Project hidden fields and forward caller context to population.
- **Acceptance:** user A cannot preview user B's restricted record; hidden data does not appear in
  output or populated targets; rejected writes cannot be smuggled through preview. Preview performs
  zero persistent writes, zero snapshot creation and no committed-mutation hooks. Local/HTTP agree.
- **Tests:** direct Local API with `overrideAccess: false`, anonymous/authenticated HTTP, hidden field,
  denied row, new document, depth 1 and no-write spies. Keep trusted override documented.
- **Handoff:** exact preview behavior and retained options for C02/S03.

### A03 — Apply target visibility during population

- **Depends on:** A01/A02 shared-policy boundary. **Scope:** runtime population/read projection,
  access tests and related contract docs. No depth expansion beyond current 0/1.
- **Deliver:** readable parent does not grant access to its target; apply target collection read
  rules, row predicates, draft visibility and field projection. Preserve batching and define omitted
  target semantics: single target null, many target omitted, unless B02 approves a documented change.
- **Acceptance:** private/draft targets stay hidden through relation and upload reads, list/single,
  preview and other supported callers; missing and inaccessible targets do not disclose distinctions.
  Test nested/localized relations for supported shapes; reject unsupported shapes explicitly rather
  than claiming they work. Trusted override remains deliberate.
- **Tests:** `populate.test.ts`, read/preview handler integration, D1/libSQL visibility fixture;
  keep the existing passwordHash regression. Measure adapter call count to prevent N+1 regression.
- **Handoff:** honest populated wire shape for C02 and supported relation matrix for D02.

### A04 — Close remaining access boundary gaps

- **Depends on:** A01–A03. **Scope:** globals and existing file/metadata/query paths, runtime tests;
  split globals and remaining-path work only if oversized or independently risky.
- **Deliver:** enumerate every retained HTTP handler and Local method against the same user/role/row/
  field matrix. For globals, apply supported access conditions or reject unsupported query-returning
  policies; do not accept then ignore them. Define and enforce global draft visibility. Check file
  routes and collection descriptions for private data and check protected-field filtering/count
  behavior for inference leaks under the intended policy.
- **Acceptance:** all inventory paths are covered; authentication failures remain 401/403 as specified,
  dependency outages remain 5xx, and no handler exposes raw internal errors. A forbidden mutation
  leaves persisted state unchanged. Tests must not rely on UI hiding the action.
- **Tests:** runtime HTTP/auth/global/file tests and one consumer forbidden-action browser case.
- **Handoff:** completed access matrix, residual findings classified, common gates and changesets.

## Acceptance criteria

Every export/route has an explicit contract and evidence or named gap packet. All retained read/write paths enforce caller, row and field policy, including passwordHash filtering. Forbidden mutations leave persisted state unchanged. Useful APIs remain retained by default.

## Required tests

Packet checks include documentation links/source comparison, coverage baseline guards, Local/HTTP denied-path regressions, real D1/libSQL visibility cases and a consumer forbidden-action journey. No tests are needed solely for prose. Common repository gates and applicable [QUALITY.md](QUALITY.md) evidence apply.
Record cached, newly run and pending evidence separately.

## Release gate

B01–B04 and A01–A04 complete, with no unresolved high-severity access bypass. Review the install → configure collections/auth → bootstrap → mount admin → manage/read content guide against tiny-project now; keep its proven limits explicit. Several coherent PRs may form this minor; do not create one giant branch.
