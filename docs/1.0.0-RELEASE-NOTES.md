# ForgeCMS 1.0.0 — stable release notes

> Published 2026-10-17 by the official main-branch release workflow. See the [release dossier](1.0-RELEASE-DOSSIER.md#l03-publication-and-closeout-2026-10-18) for evidence and remaining verification limits.

ForgeCMS 1.0.0 makes the compatibility commitment for the public surface frozen in 0.13.0 and
validated by the 0.12 certification work and the accepted `1.0.0-rc.2` candidate. This is a stable
milestone, not a feature release: the stable packages contain no executable-code change relative to
the accepted candidate. See each package's changelog for its version history.

## Stable package family

All twelve public packages are released together at `1.0.0`:

- `@forge-cms/core`, `@forge-cms/db`, `@forge-cms/auth`, `@forge-cms/storage`
- `@forge-cms/s3`, `@forge-cms/api`, `@forge-cms/runtime`, `@forge-cms/cloudflare`
- `@forge-cms/angular`, `@forge-cms/admin`, `@forge-cms/testing`, `@forge-cms/agent`

## Compatibility commitment

For the stable public surface, patch releases fix defects without breaking documented behavior,
minor releases add compatible capabilities, and breaking changes require a major release. The exact
supported ranges, tested versions, deprecation policy, server/browser boundaries, and adapter
certification scope are in [SUPPORT.md](SUPPORT.md) and [1.0-PUBLIC-SURFACE.md](1.0-PUBLIC-SURFACE.md).

Existing 0.x installations should review [Migrating to 1.0](MIGRATING-TO-1.0.md), especially the
default API paths, Angular admin peer requirements, and the documented migration and backup limits.

## Experimental capabilities and limitations

`@forge-cms/agent` remains experimental development-time tooling. Cloudflare Analytics also remains
experimental. Neither is covered by the stable 1.x compatibility promise. See
[LIMITATIONS.md](LIMITATIONS.md) for the supported boundaries, including Angular 21 for the admin,
Garage as the certified S3 service, and the absence of down migrations, point-in-time recovery, and a
visual page builder.

The accepted candidate's known findings remain as documented: the admin landmark improvement is
planned for a compatible 1.0.x release; unstyled consumer fixture target-size observations do not
represent the styled product; first-publication npm metadata and registry propagation behavior are
release-process details; optional remote J3/J4 checks were classified as non-blocking. No external
adoption feedback is claimed.
