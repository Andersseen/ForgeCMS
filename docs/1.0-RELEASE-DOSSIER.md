## G. Security

- **Access:** collection/row/field access are functions; the Local API is trusted (`overrideAccess: true`) and the HTTP layer **never** honours a caller override; relations, drafts and files are access-checked indirectly
  (target access, draft visibility, file ownership via `_storageKey`). Auth-managed collections are not writable through the generic API.
- **Sessions:** `HttpOnly`, `SameSite=Lax`, `Secure` by default, 24-hour signed token; the user row is re-read on each request, so demotions apply at once; a password change or deleted user invalidates earlier sessions.
- **CSRF:** cookie-authenticated mutations require a matching `Origin`/`Referer` (`403 FORBIDDEN`); Bearer requests are not cookie-ridable and are exempt.
- **Abuse bounds:** auth body bound 8 KiB (`413`), password length bounds, login/signup throttle hook, constant-work login for unknown emails; passwords PBKDF2 (100,000 iterations — see section J).
- **Metadata:** anonymous collection/global metadata omits fields nobody can read or write (since `0.13.3`).
- **Secrets:** browser bundles are scanned for server code and secrets on every packed consumer build (and for the quickstart); log redaction asserted (section D); S3 credentials never reach a browser bundle.
- **Machine auth:** scoped API keys, secret shown once, only a hash stored.
- **Reporting path:** [SECURITY.md](../SECURITY.md). GitHub private vulnerability reporting is **not enabled** (verified through the API on 2026-10-13); the policy documents the only real mechanism that exists (a content-free issue
  to arrange a private channel) and does not invent an address. **Release-owner action before the RC is announced:** enable _Settings → Code security → Private vulnerability reporting_ (and update SECURITY.md), or publish a
  monitored security contact.
- **Static checks:** repository secret scanning and push protection are enabled; Dependabot security updates are disabled (see section J).
