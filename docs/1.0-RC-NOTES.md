# ForgeCMS 1.0 release candidate — notes

> **ForgeCMS `1.0.0-rc.2` is a release candidate, not 1.0.** The stable line remains `0.13.4` (npm `latest`). The candidate is published, when it is, under the
> npm dist-tag **`rc`** only: `npm install @forge-cms/core@rc`. Plain `npm install @forge-cms/core` still installs `0.13.4`.

The twelve `@forge-cms/*` packages share one version. For the eleven stable packages `1.0.0-rc.2` introduces **no new feature and no API change** relative to `0.13.4`: it is the
compatibility candidate for the surface frozen in `0.13.0` and certified in roadmap 0.12 (R01–R04). The twelfth package, `@forge-cms/agent`, is new and **experimental** (spec 093). Exact commit, tarball hashes and the matrix outcome are in
the [release dossier](1.0-RELEASE-DOSSIER.md#l-l01--the-release-candidate).

## What the candidate covers

- code-first schema (`defineCollection`, `defineField`) and runtime validation
- the runtime, the Local API and the REST API with its stable envelope
- access control and authentication (browser sessions, API keys, bearer tokens)
- drafts, versions, globals and localization
- relations and uploads
- the typed Angular client, SSR and hydration
- the reusable Angular admin (Angular 21; the client SDK also supports Angular 22)
- schema upgrades with backup and restore
- Cloudflare D1/R2 and portable libSQL / S3-compatible storage (Garage certified)

## Experimental in this candidate (outside the stable promise)

- **[Agent Kit](../apps/www/src/content/docs/agent-kit.md) (`@forge-cms/agent`)** - a read-only local MCP server and an official skill pack for AI coding agents, matched to this exact version. Development tooling only; never a runtime dependency; no telemetry.
- **[Cloudflare Analytics](../apps/www/src/content/docs/analytics.md)** - privacy-minimizing pageviews with an admin dashboard, now with one verified copy-paste recipe. Still experimental.

## What it does not claim

Both capabilities above are experimental and may change in a compatible 1.x minor. There is no visual page builder. See [LIMITATIONS](LIMITATIONS.md) for the documented bounds.

## Producing the next candidate

See "Next RC after a defect" in [spec 092](specs/092-forgecms-1.0-release-candidate.md): fix with a regression test, add a changeset, `pnpm changeset:version`
(pre mode stays active), re-certify the new clean commit, then dispatch the manual `release-rc` workflow. Never edit versions by hand.
